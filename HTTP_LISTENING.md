# AI Implementation Specification: Corvo `http_listen` Block

## 1. Architectural Philosophy (Context for AI)
You are extending the compiler for **Corvo**, a purely procedural, zero-dependency scripting language compiled via Rust. Corvo strictly avoids Object-Oriented Programming (OOP), hidden call stacks, callbacks, and global state pollution.

The new `http_listen` block must be implemented as a **blocking iteration loop over incoming TCP streams.**
1. **No Callbacks:** The block executes synchronously top-to-bottom for every incoming HTTP request.
2. **Explicit State:** Request and response data must strictly live in explicitly bound Corvo `@` variables.
3. **Data Over Objects:** Incoming HTTP requests are parsed into native Corvo Map types (`type_system::value::Value::Map`). The HTTP response is strictly generated by evaluating the final state of the response Map at the end of the block.
4. **OS-Level Concurrency:** Similar to Corvo's native `async_browse`, the HTTP listener handles requests concurrently by spawning native OS threads (`std::thread::spawn`), protecting state mutations strictly via Corvo's explicit `shared` keyword and `SharedValue` wrappers.

## 3. Data Contracts: The Map Schemas

Because Corvo forbids methods like `@resp.send()`, HTTP data is modified exclusively using Corvo's standard map module (`map.get`, `map.set`). 

### 3.1 The Request Map (`@req`)
Parsed by the backend upon receiving a network payload. It is conceptually immutable for the user.
*   **`"method"`** *(Value::String)*: The HTTP verb in uppercase (e.g., `"GET"`, `"POST"`).
*   **`"path"`** *(Value::String)*: The raw URI path (e.g., `"/api/users"`).
*   **`"query"`** *(Value::Map)*: Parsed query string pairs (e.g., `?id=5` -> `{"id": "5"}`).
*   **`"headers"`** *(Value::Map)*: Incoming HTTP headers. The backend **must** normalize all keys to lowercase.
*   **`"body"`** *(Value::String)*: The raw string payload of the request.
*   **`"ip"`** *(Value::String)*: The connected client IP.

### 3.2 The Response Map (`@resp`)
Injected into the block's `Scope` at the start of every iteration with default values. The user explicitly overwrites these values.
*   **`"status"`** *(Value::Integer)*: Defaults to `200`.
*   **`"headers"`** *(Value::Map)*: Defaults to `{"content-type": "text/plain"}`.
*   **`"body"`** *(Value::String)*: Defaults to `""`.

## 4. Runtime & Execution Semantics (`compiler::evaluator::Evaluator`)

When the interpreter encounters `Stmt::HttpListen`, implement this pipeline:

1.  **Evaluate Port:** Evaluate the `port` expression into a `Value::Integer`. Panic or return a `CorvoError` if it is not an integer or is out of bounds.
2.  **Bind Server:** Use `std::net::TcpListener::bind` to **block the main thread**.
3.  **The Accept Loop:** For each stream in `listener.incoming()`:
    *   Parse the raw TCP stream into the `@req` Map and initialize the default `@resp` Map.
    *   **Scope Isolation:** Instantiate a fresh `runtime::scope::Scope`.
        *   Insert the `@req` and `@resp` maps.
        *   For each string in `shared_vars`, extract it from the outer scope as a `SharedValue` (Corvo's native `Arc<Mutex<Value>>` wrapper) and clone the reference into the new local scope.
    *   **Concurrency:** Spawn a native OS thread (`std::thread::spawn`).
    *   **Execution:** Inside the thread, instantiate a new `Evaluator` and execute the `body` statements using the isolated `Scope`.
4.  **Response Flush:** When block execution finishes, extract the final state of the variable named by `resp_ident` from the `Scope`. Validate it is still a `Value::Map`. Construct a raw HTTP response string using its `"status"`, `"headers"`, and `"body"` keys, write it to the TCP stream, and cleanly close the connection.

## 5. Corvo Implementation Examples (For Test Generation)

*Instruct the AI to use these precise patterns to generate end-to-end integration tests in Rust to ensure the new block behaves correctly.*

### Example A: Basic Native Routing
```corvo
sys.echo("Starting server on port 8080...")

http_listen(port: 8080, @req, @resp) {
    # Combine method and path to natively utilize Corvo's structural match syntax
    @route = "${@req["method"]} ${@req["path"]}"
    
    match(@route) {
        "GET /" => {
            @resp = map.set(@resp, "body", "Home")
        },
        "GET /greet" => {
            # Safely extract query parameters with fallback
            @name = map.get(@req["query"], "name", "stranger")
            @resp = map.set(@resp, "body", "Hello, ${@name}!")
        },
        _ => {
            # 404 Fallback utilizing standard map reassignments
            @resp = map.set(@resp, "status", 404)
            @resp = map.set(@resp, "body", "Not Found")
        }
    }
}
```

### Example B: Concurrent State Mutation using `shared`
```corvo
@hit_count = 0

sys.echo("Analytics server running on port 3000...")

# The 'shared' keyword safely passes the variable into the OS thread via SharedValue
http_listen(port: 3000, @req, @resp, shared @hit_count) {
    
    # Acts as "Middleware" - increments safely on every single concurrent request
    @hit_count = @hit_count + 1
    
    if (@req["path"] == "/stats") {
        @resp = map.set(@resp, "status", 200)
        @resp = map.set(@resp, "body", "Total concurrent server hits: ${@hit_count}")
    } else {
        @resp = map.set(@resp, "status", 404)
    }
}
```

### Example C: JSON REST API (Synergizing with standard lib)
```corvo
http_listen(port: 5050, @req, @resp) {
    @route = "${@req["method"]} ${@req["path"]}"
    
    match(@route) {
        "POST /users" => {
            # Parse incoming JSON payload using standard lib
            @payload = json.parse(@req["body"])
            @username = map.get(@payload, "username", "anonymous")
            
            # Build standard Map response
            @response_data = map.new()
            @response_data = map.set(@response_data, "success", true)
            @response_data = map.set(@response_data, "message", "User ${@username} created")
            
            @resp = map.set(@resp, "status", 201)
            
            # Nested Map updating for headers
            @headers = map.get(@resp, "headers")
            @headers = map.set(@headers, "content-type", "application/json")
            @resp = map.set(@resp, "headers", @headers)
            
            # Stringify to standard String body
            @resp = map.set(@resp, "body", json.stringify(@response_data))
        },
        _ => {
            @resp = map.set(@resp, "status", 405)
        }
    }
}
```

## 6. AI Edge-Cases Checklist
- [ ] **Type Enforcement Phase:** Ensure the final extraction phase strictly validates that `@resp` is still a `Value::Map` and `status` is a `Value::Integer`. If the user accidentally performed `@resp = "string"`, return a hard-coded HTTP `500 Internal Server Error` to the network client instead of crashing the Rust evaluator.
- [ ] **Port Conflicts:** If `TcpListener::bind` fails (e.g., port already in use), map it to a cleanly formatted `CorvoError` and halt script execution prior to loop entry.
- [ ] **Missing Shared Declaration:** If a user attempts to update outer-scope variables inside the block *without* adding them to the `shared` comma-separated list, standard Corvo lexical scope-shadowing rules must naturally isolate and drop those changes upon thread completion. Do not allow implicit state leaks.
