## How to regenerate

From the repository root:

```bash
CORVO_LANG_LOCAL_PATH="$(pwd)" \
  cargo test --test benchmark_compile generate_benchmark_report -- --ignored --nocapture
```

This overwrites this file. Temporary artifacts use `tempfile` directories and are removed when the test process exits.

### On GitHub Actions

Use the **Benchmark (manual)** workflow (`.github/workflows/benchmark.yml`): **Actions → Benchmark (manual) → Run workflow**. When the job finishes, open **Summary** and download the **`benchmark-results-*`** artifact; it contains an updated `BENCHMARK.md` and `benchmark_run.log`.

### Optional environment variables

| Variable | Effect |
|----------|--------|
| `CORVO_BENCHMARK_LIMIT` | Maximum number of `examples/*.corvo` files (after sorting, with `hello.corvo` moved first). Default: all (50 files). |
| `CORVO_BENCHMARK_SKIP_PER_FILE_COLD` | If `1`, skips the **fresh cache per example** phase (each phase does a full dependency rebuild; very slow for large sets). |

### What is measured

| Scenario | Description |
|----------|-------------|
| **Compile — cold cache** | New empty `CORVO_CACHE_DIR`; first example is `examples/hello.corvo` (moved before the rest alphabetically). Times the `Compiler::compile` path (includes `cargo build --release` inside the Corvo compile workspace). |
| **Compile — warm cache** | Same `CORVO_CACHE_DIR` as cold; second example in the list. |
| **Compile — shared cache** | Every listed example compiled sequentially reusing the same cache (typical incremental behavior after dependencies are built). |
| **Compile — no shared cache** | Each example gets a **new** temporary `CORVO_CACHE_DIR` (cold dependency build every time). Optional skip via env above. |
| **Transpile — single project** | All examples transpiled into **one** Cargo package (multiple `[[bin]]` targets), then one `cargo build --release`. |
| **Transpile — many projects** | Each example transpiled into its **own** Cargo package, each followed by `cargo build --release`. |

`CORVO_LANG_LOCAL_PATH` must point at this repo so the generated `Cargo.toml` resolves `corvo-lang` via `[patch.crates-io]` (same approach as other integration tests). Nested `cargo` invocations clear inherited `CARGO_TARGET_DIR` so artifacts land under each project’s `target/` directory.
